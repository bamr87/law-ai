# Law AI — Backlog

> **Append-only** register of follow-ups discovered during implementation. Every `/implement` cycle MUST append discovered work here in addition to closing the current task. Items graduate from this list into `specs/NNN-*/` via `/specify`.
>
> **Format**: One bullet per item, kebab-case ID, status, brief context, link to the spec/PR that surfaced it.

## Conventions

| Field        | Notes                                                                  |
| ------------ | ---------------------------------------------------------------------- |
| `id`         | `BL-YYYYMMDD-NN` — the date discovered + an ordinal                    |
| `status`     | `open` / `claimed-by:specs/NNN` / `wontfix` (with reason) / `done`     |
| `kind`       | `feature` / `refactor` / `tech-debt` / `test-gap` / `doc-gap` / `infra`|
| `severity`   | `low` / `med` / `high`                                                 |
| `surfaced-in`| Spec or PR that discovered it                                          |

## Triage rules

1. New items go to **Open**. Promotions go to **Claimed**. Resolved items move to **Done** (kept for audit; never delete).
2. Items unclaimed > 60 days get reviewed at the next `/specify` cycle and either closed `wontfix` or escalated.
3. CI gate (`scripts/backlog_lint.py`) enforces format and forbids deletion of historical entries.
4. Ids are unique file-wide, and two branches open on the same day will both reach for that day's `-01`. The collision only surfaces once both merge, so the branch that merges **second** renumbers to the next free ordinal — its ids are the ones no merged PR has quoted yet. Renumbering must never drop an id: rule 3's append-only check compares the id *set* against the previous commit, so move an id forward, never delete one.
5. Ids are `BL-YYYYMMDD-NN` where the date is the **discovery** date; the ordinal caps at 99 per date. The 2026-09-05/06 backlog-zero sweep exhausted both days, so ten follow-ups discovered on the 6th carry 2026-09-07 ids. Tracked as BL-20260907-11.

Fix by giving the two a single owner — bind `Enter` once in Drill and let it submit or advance — rather than by ordering listeners, which is not something effect order can guarantee. _Surfaced in:_ the #117 drill-position fix (found by a regression test that tried to grade question 2 from the keyboard).
