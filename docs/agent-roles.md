# Law AI — Agent Roles & Specifications

This document defines every agent that exists or is planned for Law AI. All agents must follow the rules in `AGENTS.md`.

Status markers used below: **Live** (real implementation, exercised by tests), **Stub** (class exists and is wired up, but the core logic is an honest no-op placeholder), **Not started** (no code anywhere in the repo). This mirrors the actual set under [backend/law_ai/agents_runtime/crews/](../backend/law_ai/agents_runtime/crews/) and [backend/law_ai/agents_runtime/graphs/](../backend/law_ai/agents_runtime/graphs/), and the registered set in [backend/law_ai/agents_runtime/registry.py](../backend/law_ai/agents_runtime/registry.py).

Runtime LLM note: every "Live" agent below that calls an LLM does so through the shared provider chain in `law_ai.core.llm` — Claude over OAuth, then Claude over `ANTHROPIC_API_KEY`, then local Ollama as the last-tier fallback (`LLM_PROVIDER_CHAIN`, spec 034; see [CLAUDE.md](../CLAUDE.md) "Runtime LLM policy" and [docs/constitution.md](constitution.md) §1). None of these agents are CrewAI `Crew`/`Agent`/`Task` objects — despite the `crews/` directory name, they are plain Python classes with an async `run()`; no file under `agents_runtime/crews/` imports `crewai`.

## Planned Agents (Post-MVP)

- **ContractRiskAssessor** — Clause classification + obligation extraction + risk scoring (uses CUAD + LEDGAR patterns)
- **StatuteChangeDetector** — Monitors legislation.gov.uk / EUR-Lex for amendments affecting user's saved cases
- **CaseOutcomePredictor** — Predicts likely outcome based on similar fact patterns + judge history (research only)
- **MultiJurisdictionComparator** — Side-by-side analysis across US/UK/EU on same legal issue
